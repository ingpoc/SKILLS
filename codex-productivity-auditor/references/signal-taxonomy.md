# Signal Taxonomy

Use this reference to convert repeated session behavior into durable setup.

## Strong Signals

- Same correction appears in multiple turns or sessions.
- User explicitly says the behavior should become default.
- A repeated command has an obvious one-click local environment action shape.
- A stale or duplicate owner surface caused confusion.
- The same tool/plugin preference is repeated after a wrong substitution.

## Weak Signals

- One-off preference with no recurrence.
- A correction tied to a single temporary branch or incident.
- User preference conflicts with current official docs.
- Recommendation depends on missing transcript or repo evidence.

## Owner Mapping

- Repeated always-loaded instruction: `AGENTS.md`.
- Repeatable workflow: skill or workflow doc.
- Deterministic safety check: test, lint, or narrow hook.
- Noisy proof work: subagent.
- Stable recurring maintenance: automation.
- External service access: plugin or MCP.
- User/project lesson: memory.

## Confidence Labels

- High: repeated signal plus repo/current-doc evidence.
- Medium: one strong signal or multiple weak signals with plausible owner.
- Low: incomplete evidence or likely drift; recommend a probe, not setup.
